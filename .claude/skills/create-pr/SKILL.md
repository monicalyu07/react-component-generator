# create-pr

현재 브랜치의 변경사항을 분석해 PR 템플릿에 맞는 본문을 작성하고 `gh`로 Pull Request를 생성한다.

이 스킬은 `context: fork`로 서브 에이전트에서 실행된다. 서브 에이전트는 사용자에게 중간에 되물을 수 없으므로, 판단이 필요한 지점마다 아래의 기본 규칙을 따르고, 진행할 수 없는 상황이면 **무엇이 막혔고 어떻게 풀지** 를 최종 보고에 적고 멈춘다. 최종 보고만 사용자에게 전달되므로, 보고에는 PR URL과 내린 판단(언어, base 브랜치)을 반드시 담는다.

## 인자

| 인자 | 의미 |
|------|------|
| `--lang en\|ko` | 템플릿 언어를 강제한다. 자동 감지보다 우선한다. |
| `--base <branch>` | PR 대상 브랜치. 없으면 저장소 기본 브랜치를 쓴다. |
| `--draft` | 초안(draft) PR로 만든다. |

## 절차

### 1. 사전 점검

아래 중 하나라도 해당하면 PR을 만들지 않고 이유와 해결 방법을 보고한 뒤 멈춘다. PR은 팀원에게 보이는 외부 작업이라, 애매한 상태에서 진행하기보다 멈추는 편이 안전하다.

- `gh auth status`가 실패한다 → `gh auth login`이 필요하다고 안내한다.
- 현재 브랜치가 base 브랜치와 같다(예: `main`에서 실행) → 작업 브랜치를 먼저 만들라고 안내한다.
- 커밋되지 않은 변경(`git status --porcelain`)이 있다 → PR에 빠질 수 있으므로 `/commit`을 먼저 실행하라고 안내한다. 이 스킬이 대신 커밋하지 않는다.
- base 대비 앞선 커밋이 없다(`git log <base>..HEAD`가 비어 있다).
- 같은 브랜치의 열린 PR이 이미 있다(`gh pr view --json url,state`) → 중복 생성하지 말고 기존 PR URL을 보고한다.

### 2. base 브랜치 결정

1. `--base`가 있으면 그것을 쓴다.
2. 없으면 `gh repo view --json defaultBranchRef,isFork,parent`로 기본 브랜치를 얻는다.
3. 포크 저장소이고 `origin`이 사용자의 포크라면, PR 대상은 보통 upstream(`parent`)이다. 이 경우 `gh pr create --repo <parent>`와 `--head <user>:<branch>` 형태를 사용한다.

### 3. 변경사항 수집

- `git log <base>..HEAD --format='%h %s%n%b'` — 커밋 목록과 본문
- `git diff <base>...HEAD --stat` — 변경 규모
- `git diff <base>...HEAD` — 실제 변경. 너무 크면 핵심 파일 위주로 읽는다.

PR은 커밋 하나가 아니라 브랜치 전체의 변경을 설명한다. 마지막 커밋만 보고 쓰면 앞선 작업이 빠진다.

### 4. 템플릿 언어 선택

아래 순서로 판단하고 처음 확정되는 결과를 쓴다.

1. `--lang`이 있으면 그것을 쓴다.
2. 저장소에 자체 PR 템플릿(`.github/pull_request_template.md`, `.github/PULL_REQUEST_TEMPLATE/`)이 있으면 그 구조와 언어를 따른다. 메인테이너가 요구하는 형식이 우리 템플릿보다 우선하기 때문이다. 이 경우 아래 `references/` 템플릿은 쓰지 않는다.
3. 아래 신호를 보고 프로젝트가 한국어권인지 판단한다.
   - base 저장소의 최근 머지된 PR 제목 (`gh pr list --state merged --limit 10 --json title`)
   - 최근 커밋 메시지 (`git log -20 --format=%s`)
   - `README.md`의 본문 언어
   - 포크라면 upstream 저장소의 위 신호
   
   한글이 절반 이상이면 **한국어**, 거의 없으면 **영문**으로 정한다.
4. 신호가 엇갈리거나 부족하면 한국어를 쓴다. 이 스킬을 쓰는 프로젝트가 대체로 한국어 프로젝트이기 때문이다. 대신 최종 보고에 "언어를 자동 감지로 정했다"고 밝혀 사용자가 `--lang`으로 다시 실행할 수 있게 한다.

선택한 언어에 맞는 파일 **하나만** 읽는다.

| 언어 | 템플릿 |
|------|--------|
| 영문 | `references/pr-template.en.md` |
| 한국어 | `references/pr-template.ko.md` |

### 5. 제목과 본문 작성

**제목**
- 프로젝트의 기존 커밋/PR 제목 스타일을 따른다. 이 저장소처럼 `<type>: <요약>` 형식(`feat`, `fix`, `refactor`, `chore`)을 쓰면 그대로 쓴다.
- 70자 이내, 마침표 없음.
- 영문 템플릿이면 영어 명령형(`feat: add prompt length validation`), 한국어 템플릿이면 한국어로 쓴다.

**본문**
- 템플릿의 섹션 제목과 순서를 유지하고 `<!-- -->` 안내 주석은 지운다.
- 해당 사항이 없는 선택 섹션은 빈 채로 두지 말고 섹션째 삭제한다. 빈 섹션은 리뷰어에게 노이즈다.
- "무엇을 바꿨는지"는 diff에서 읽히므로, "왜 바꿨는지"와 리뷰어가 주의할 지점에 글자를 더 쓴다.
- 테스트 방법에는 실제로 실행해 본 명령만 적는다. 실행하지 않은 검증을 한 것처럼 쓰지 않는다. 확인하지 못했으면 그렇게 적는다.
- 관련 이슈 번호가 커밋 메시지나 브랜치 이름에 있으면 `Closes #N`으로 연결한다. 추측해서 만들지 않는다.
- 본문 마지막 줄은 템플릿에 포함된 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`를 그대로 유지한다.

### 6. 푸시와 PR 생성

1. 원격에 브랜치가 없거나 로컬이 앞서 있으면 `git push -u origin HEAD`로 푸시한다. `--force`는 쓰지 않는다. 거부되면 이유를 보고하고 멈춘다.
2. 본문을 임시 파일에 쓰고 `--body-file`로 넘긴다. 한글·백틱·따옴표가 셸 인용에서 깨지는 것을 피하기 위해서다.
   ```bash
   gh pr create --base <base> --title "<title>" --body-file <tmpfile> [--draft] [--repo <parent> --head <user>:<branch>]
   ```
3. 생성 후 임시 파일을 지운다.

### 7. 최종 보고

사용자에게 아래를 짧게 전달한다.
- PR URL
- 제목
- base ← head 브랜치
- 사용한 템플릿 언어와 그 근거 (`--lang` 지정 / 저장소 자체 템플릿 / 자동 감지)
- 막혀서 만들지 못했다면 이유와 다음 행동

## 하지 않는 것

- 변경사항을 대신 커밋하지 않는다. 커밋 분류와 메시지는 사용자 승인 절차가 있는 `/commit`의 몫이다.
- `--force` 푸시, base 브랜치 직접 푸시, 기존 PR 덮어쓰기를 하지 않는다.
- PR 머지, 리뷰어 지정, 라벨 부여는 하지 않는다. 요청받지 않은 외부 작업이다.
